# Public beta release checklist

Use this checklist before publishing a Pdf++ beta release.

## Repository

- [ ] The repository contains no build directories, archives, credentials, absolute local paths, or private documents.
- [ ] Every bundled PDF, image, font, and third-party source has a redistributable license.
- [ ] `LICENSE`, `NOTICE`, `README.md`, `SECURITY.md`, and `CONTRIBUTING.md` are present.
- [ ] The CMake project version matches `CPPPdf::VersionString` and the release tag.
- [ ] The feature matrix and known limitations reflect the current implementation.

## Validation

- [ ] Ubuntu GCC strict build passes.
- [ ] Ubuntu Clang strict build passes.
- [ ] Windows MSVC strict build passes.
- [ ] AddressSanitizer and UndefinedBehaviorSanitizer pass.
- [ ] All unit and integration tests pass.
- [ ] Generated sample PDFs pass independent validation when available.
- [ ] Reader, writer, extraction, search, and renderer benchmark baselines are recorded.

## Release

- [ ] Update `CHANGELOG.md`.
- [ ] Tag the release as `v<version>-beta.<number>` while the project is pre-1.0 beta.
- [ ] State that rendering is experimental and security-sensitive features are incomplete.
- [ ] Publish source archives generated by GitHub rather than committing ZIP files.
- [ ] Create follow-up issues for known regressions and unsupported PDF features.
